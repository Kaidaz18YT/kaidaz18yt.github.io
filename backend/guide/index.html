Quick answers

Start here if you only need the essentials.
What is AFO Backend?

A backend-as-a-service, similar to Firebase or PocketBase. One service hosts multiple projects, each with separate users, data, API keys and access rules.

How do I get access?

Ask the admin to create your project in the dashboard. You need its project slug and client API key.

Can I put the API key in my website?

The client key is designed for frontend use. The admin key is secret—keep it on a server and never put it in browser code, a public repository or an app bundle.

Do I need to create collections first?

No. Collections are created automatically when you first write to them. Access rules are configured by the admin in the dashboard.

Why is my request being denied?

Check your project slug, client key and (for protected actions) bearer token. If those are correct, ask the admin to review the project's Rules in the dashboard.

How do I check if the server is up?

Request https://kaidaz18.duckdns.org/api/health. A healthy server returns 200 OK.

03 · Send credentials
Include the right headers

Send x-api-key on every API request; add a bearer token for authenticated actions.

!
Keep the admin key private. The client key is okay in frontend code; the admin key must only be used from trusted server-side code.
What credentials will I receive?

Project slug (for example, my-website) identifies your project in API URLs.

Client API key (starts with ck_live_) authenticates public/frontend requests.

Admin API key (starts with ak_live_) is secret and intended for server-side use only.

API endpoints

All client-facing API requests use this URL pattern.
https://kaidaz18.duckdns.org/api/v1/{project-slug}/...

Example request and headers

Use the client key in x-api-key. For signed-in actions, also send Authorization: Bearer <token>. Include Content-Type: application/json on POST and PATCH requests.

POST /api/v1/my-website/auth/login
Content-Type: application/json
x-api-key: ck_live_...

{"email":"user@example.com","password":"password123"}

JavaScript SDK

The easiest way to connect from a JavaScript project.

Add the SDK script to your page. Alternatively, download afo-client.js and host it locally, for example at public/sdk/afo-client.js.

ADD THE SDK
<script src="https://kaidaz18.duckdns.org/sdk/afo-client.js"></script>
INITIALIZE, SIGN IN AND USE A COLLECTION
const afo = new AFOClient({
  baseUrl: "https://kaidaz18.duckdns.org",
  projectSlug: "my-website",
  apiKey: "ck_live_abc123..."
});

// Sign up (optional) or log in
await afo.auth.signup("user@example.com", "password123");
const { token } = await afo.auth.login("user@example.com", "password123");

// Create and list documents
await afo.collection("posts").create({
  title: "Hello World",
  body: "My first post!"
});
const posts = await afo.collection("posts").list();
Prefer not to use the SDK? See a fetch example

For JSON requests, include the content type and client key. Use the token returned by login for actions that require authentication.

const BASE = "https://kaidaz18.duckdns.org/api/v1/my-website";
const API_KEY = "ck_live_abc123...";

// Log in
const res = await fetch(`${BASE}/auth/login`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-api-key": API_KEY
  },
  body: JSON.stringify({
    email: "user@example.com",
    password: "password123"
  })
});
const { token } = await res.json();

// Create a document
await fetch(`${BASE}/collections/posts`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-api-key": API_KEY,
    "Authorization": `Bearer ${token}`
  },
  body: JSON.stringify({ title: "My Post", content: "Hello!" })
});

Before you ship

A short checklist for a reliable integration.
  • Get the project slug and client API key from the admin.
  • Set the base URL to https://kaidaz18.duckdns.org.
  • Include x-api-key on every API request.
  • Use Authorization: Bearer <token> for authenticated actions.
  • Use any collection name; it is created on first write.
  • Test GET /api/health to confirm connectivity.
Important notes

Collections are created automatically when first written to. No collection setup is needed.

Access rules are set by the admin in the dashboard under Rules. A denied request may mean a rule needs adjusting.

The client API key is intended for frontend use; the admin key is not. All responses are JSON. Add Content-Type: application/json to POST and PATCH requests.

Health check: GET https://kaidaz18.duckdns.org/api/health returns 200 OK when the server is running.
